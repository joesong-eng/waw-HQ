### 4. 設備識別實作細節

**檔案**: `src/iHubDevice.js`

**識別層級**（優先順序）：
1. **硬體穩定 ID**: `window.median.deviceInfo().hardwareId` 或 `androidId`
2. **原生 Bridge**: `window.AndroidBridge.getAndroidId()`
3. **本地儲存**: `localStorage.getItem('v9_ihub_deviceId')`
4. **硬體指紋鎖**: 基於 `model + osVersion + hardware + androidSha1` 的多重特徵雜湊

**環境檢測**：
```javascript
function isApkEnvironment() {
    if (window.AndroidBridge || window.median || window.JSBridge) return true;
    const ua = navigator.userAgent;
    return (ua.includes('Median') || ua.includes('LeanWebView') || ua.includes('; wv)'));
}
```

## 🎯 結論

### APK 狀態：**已實作 WebView 相容層，但無本地打包能力**

**現況說明**：
1. iHub 前端已完整實作 Android WebView 相容邏輯
2. 設備識別模組支援多種 Bridge（Median、AndroidBridge、JSBridge）
3. **打包依賴外部平台**（Median.co），非本地自主打包

**架構特點**：
- ✅ 輕量化：無需維護原生 Android 代碼
- ✅ 快速迭代：Web 更新即時生效
- ❌ 依賴第三方：APK 打包需透過 Median.co 平台
- ❌ 無原生能力：無法直接訪問 USB-Serial（需透過 VPS `credit-api` 中繼）

### 建議行動

**若需自主打包能力**，需要：
1. 引入 Capacitor 或 Cordova 框架
2. 配置 `android/` 原生專案
3. 建立本地打包腳本
4. 配置簽名憑證

**若維持現有方案**，需要：
1. 補充 Median.co 打包 SOP 文件
2. 記錄 APK 版本與發布歷史
3. 建立 OTA 更新機制文件
