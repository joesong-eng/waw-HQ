## 一、提報背景與痛點檢討

現行 `https://ali.tg25.win/devices` 燒錄頁面經實務驗證，存在多項嚴重脫節與邏輯紊亂：

1. **使用者視角混淆**：
   - 頁面充斥底層 Terminal hex log、空狀態報錯，讓產線作業員老邱在辦公室操作時無所適從。
2. **缺乏智慧自動分流**：
   - 即使訂單純粹為「通訊卡」，仍強迫顯示「Step 3 平板配對」與無關選項；純配件訂單未被過濾。
3. **出廠標籤列印繁冗**：
   - 燒錄後需手動點擊「提交紀錄」再另開預覽，操作步調破碎。
4. **重大業務遺漏 —— 售後維修換機**：
   - 當客戶（如李董）舊平板故障，單獨向老邱加購新平板時，訂單中無卡片可燒錄，目前系統**完全無法將新平板綁定回客戶店裡的既有機台**。客戶收到新平板開機只會看到 404（未配對）。

## 二、老邱視角重構藍圖 (4+1 架構)

### 1. 頂部常駐：目標訂單看板與進度地圖
- **訂單過濾**：僅列出「需加工/出廠」之訂單（包含需燒錄之卡片，或需配對出廠之獨立平板）。
- **常駐看板**：選定訂單後固定於頂部，清晰顯示：
  - 客戶姓名、訂單編號。
  - 當前加工即時進度（例：通訊卡 需 1 / 已完成 0；兌幣卡 需 2 / 已完成 1）。
- **動態步驟地圖（Stepped Progress Bar）**：
  - **通訊卡（3 步直線）**：`① 接駁設備` ➔ `② 燒錄通訊卡` ➔ `③ 印標籤貼卡`
  - **兌幣卡（5 步閉環）**：`① 接駁設備` ➔ `② 燒錄兌幣卡` ➔ `③ 印標籤貼卡` ➔ `④ 平板下載 APK & 聯網` ➔ `⑤ 一鍵配對綁定`

### 2. 智慧卡片／韌體自動判定（作業員零思考）
- 僅有通訊卡時：鎖定通訊卡，不提供切換，隱藏所有平板與配對功能。
- 僅有兌幣卡時：鎖定兌幣卡，燒錄完成後引導出貨平板配對。
- 雙卡並存時：以高對比大卡片按鈕顯示待處理項目與剩餘張數，老邱點擊即入對應工序。

### 3. 作業核心區：單步沉浸式流動
- **偵測**：點擊「🔌 偵測設備」，綠燈抓取晶片；失敗時顯示「按住 BOOT 點一下 RST」白話指引。
- **燒錄**：按鈕自動亮起「⚡ 開始燒錄」，跑進度條。
- **自動化入庫與印標**：進度達 100% 後，系統**自動調用 API 寫入資料庫並派發 `public_token`**，按鈕無縫轉為綠色「🖨️ 列印標籤 (貼卡)」。
- **下一張**：老邱貼標後點擊「👉 燒錄下一張」，自動重置工序並累加進度。

### 4. 兌幣卡出廠：專屬平板配對
- 燒完兌幣卡後，進入步驟 ④ 顯示「📱 準備現場出貨平板」與「iHub APK 下載 QR Code」。
- 步驟 ⑤ 輪詢列出剛開機之平板（Android ID），老邱點選「🔗 一鍵配對出貨」，完成卡片與平板關聯。

### 5. 【新增】售後換機支援（維修補單模式）
- 當訂單為「獨立加購/更換平板」時，進入「售後平板替換」專屬模式：
  - 抓取該客戶現有在線運作之機台清單（如 `kiosk_001`）。
  - 老邱將開機連網之新平板，一鍵選取「替換至 kiosk_001」。
  - 系統更新 `ali_device_bindings` 與 `kiosks` 之 `screen_mac`，新平板立即就緒，開箱即用。
