## 一、提報背景

Joe 指示從「老邱（使用者）實際操作視角」出發，逐層分析現有站點的頁面編排是否人性化。

核心原則：**用戶正在做的事情不能被打斷**——例如老邱開訂單到一半，發現缺一個客戶，不應該跳去另一個頁面新增完再回來重填，而應該在原地用彈窗新增、關閉後訂單資料還在。

> **獨立頁面** = 用戶主動來這裡瀏覽管理  
> **彈窗(Modal)** = 用戶正在做別的事，臨時需要新增，不能跳走

### 彈窗（8 個）

| # | 彈窗 | 從哪裡觸發 | 為什麼是彈窗 |
|---|---|---|---|
| A | 新增客戶 | 訂單新增/編輯頁 | 老邱開單到一半發現沒有老李 → 彈窗新增 → 關掉 → 訂單還在 |
| B | 新增介紹人 | 訂單新增/編輯頁 | 開單時想指定介紹人但下拉沒有 → 彈窗新增 → 選回來 |
| C | 快速新增產品 | 訂單新增/編輯頁 | 開單時發現缺一個產品 → 彈窗快速建品 → 關掉繼續選 |

| H | 月份篩選 | 結算列表 | 選月份 → 即時更新列表 |

### 彈窗技術方案

所有彈窗用 AJAX 提交，成功後返回 JSON，前端 JS 動態更新下拉選單，**頁面不刷新，表單資料完全不動**。

## 五、訂單狀態流程規劃

### 現有（太粗）
```
draft → completed
```

### 規劃（完整中間狀態）
```
draft（開單中）
  ↓ 確認訂單內容
confirmed（已確認）
  ↓ 有韌體產品？是 → 進入燒錄
burning（燒錄中）
  ↓ 所有設備燒完
burned（已燒錄）
  ↓ 不需燒錄直接到這
ready_to_ship（待出貨）
  ↓ 確認出貨
shipped（已出貨）
  ↓ 確認送達
completed（已完成）
```
