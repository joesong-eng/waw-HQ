## 📌 一、 提報背景與核心問題

在針對 HQ 派發之「SignalHub 全功能 E2E 閉環測試（老邱出貨 3 台 S3 採集卡給老李）」進行業務與代碼對齊盤點時，發現 Alliance 與核心資產庫存在**跨庫鏈條斷裂**之歷史遺留問題：

1. **現況斷鏈**：老邱在 Alliance 完成燒錄與出貨（`OrderController::ship`）時，設備僅存在於 Alliance 本地資料庫之 `ali_device_bindings` 表，**並未同步寫入核心共用庫 `waw_core.devices`**。
2. **斷鏈根因**：歷史 Commit `672892c` 時，因當時 Alliance 嘗試寫入 `devices` 表所沒有的欄位（`mac_address`、`node_id`）導致 SQL 報錯，當時工程師為維持燒錄站正常運作，緊急移除了跨庫寫入邏輯，自此兩邊資料流中斷。
3. **下游阻斷**：SignalHub（老李）查詢待設置採集卡時，直接依賴 `waw_core.devices` 查詢 `owner_id = 11 AND status = 'pending_setup'`。因為核心庫缺漏資料，導致老李前端無法看見「⚠️ 待設置採集卡」，業務閉環無法自動推進。

為徹底解決此斷鏈問題，建議由 HQ 統一協調以下兩步驟：

### 步驟 1：HQ 派工 Ina 進行 Schema 與寫入規格審核
- 請 Ina 審定 `iotv9.devices` 的入庫規格標準（確保符合 WAW 2.0 雙產權與 SignalHub 需求）：
  - `chip_id`: VARCHAR(50), UNIQUE
  - `owner_id`: 購買業主 ID
  - `collector_owner_id`: 採集卡擁有者 ID

  - `name`: 出貨品名（如「S3採集卡」）
  - `type`: 'arcade' 或 'other'
  - `status`: 'pending_setup'（觸發 SignalHub 設置精靈）
