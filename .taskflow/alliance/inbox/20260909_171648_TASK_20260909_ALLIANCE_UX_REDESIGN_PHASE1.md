## 🔑 Joe 確認之 7 項裁示

### 1. 介紹人定位：純紀錄，無登入

- 介紹人**沒有登入權限**，只是一個紀錄
- 建一張 ali_referrals 簡表：姓名、電話、email、line_id
- 訂單開單時下拉選擇介紹人
- 月底老邱 email / LINE 發一張佣金報表給介紹人
- **不做登入帳號，不是 AliPartner**

### 2. 客戶管理：繼續用 User 表

- 客戶 = 有登入權限的店家或機台老闆
- 買了採集卡設備後，登入看到自己的設備，做設置（SignalHub 接手）
- 繼續用 User 表（role=owner），新增客戶列表頁管理
- 客戶列表頁功能：搜尋、查看客戶底下有哪些設備

### 3. 燒錄體驗改善

目前問題：側邊欄排序太後面（第 6 位），老邱不容易找到；開完單不能直接跳去燒錄；沒有中間狀態看不出進度。

改善項目：
- 側邊排序重排：儀表板 → 訂單管理 → 燒錄與配對 → 客戶管理 → 產品管理 → 合作夥伴 → 結算管理 → 個人資料
- 訂單詳情頁直接加入「前往燒錄」按鈕，無縫跳轉燒錄站並帶入 order_id
- 開單頁 4 個 AJAX 彈窗（新增客戶、新增介紹人、快速新增產品、新增夥伴），彈窗送出成功後更新下拉選單，頁面不刷新、表單資料完全不動

### 4. 彈窗技術方案

- AJAX + JSON 回傳方向**批准**
- 每個彈窗對應一個 API endpoint（store 回傳 JSON）
- 成功後前端 JS 動態更新下拉選單

### 5. 韌體出貨款機制

**業務邏輯**：硬體是老邱自己進貨的成本，跟 Joe 無關。韌體是 Joe 開發的，每出貨一塊硬體就要紀錄一筆韌體出貨款（software_license_fee），月結付給 Joe。

具體需求：
- 每次出貨（ship()）時，對每台已綁定的設備自動建立一筆「韌體出貨款」記錄
- 記錄內容：訂單 ID、order_item_id、chip_id、產品、金額（= product.software_license_fee）、供應商=Joe、出貨日期、狀態=未結清
- 建議新建 ali_firmware_royalties 表（或類似名稱）存放這些記錄
- 月結報表：按月彙總，顯示 總出貨台數 × 單價 = 應付總額，支援 Email/PDF 發送
- 結清操作：老邱月結付款後標記「已結清」，記錄結清日期

### 6. 供應商（Joe）特殊帳號

- Joe 有特殊登入帳號，登入後：
  - 能查看全部 Alliance 資料數據（admin 等級視角）
  - 能查看自己的韌體出貨款報表帳單
  - 能核對老邱月結付款狀況（已付/未付/部分結清）
  - 歷史帳單回顧
- 供應商角色不侷限於 Joe 一人，未來可能有其他供應商，設計時考慮 supplier 概念
- User 表新增 role 或用欄位區分 supplier 身分

### 7. 訂單狀態機改造

從現有 2 步改為 7 步，涉及 DB enum + Controller + Blade 全鏈路，**Joe 已授權全鏈路改造**。

```
draft（開單中）
  ↓ 確認訂單內容
confirmed（已確認）
  ↓ 有韌體產品？是 → 進入燒錄
burning（燒錄中）
  ↓ 所有設備燒完
burned（已燒錄）
  ↓ 不需燒錄直接到這
ready_to_ship（待出貨）
  ↓ 確認出貨
shipped（已出貨）  ← 此時觸發韌體出貨款記帳 + syncDevicesToCore
  ↓ 確認送達
completed（已完成）
```
