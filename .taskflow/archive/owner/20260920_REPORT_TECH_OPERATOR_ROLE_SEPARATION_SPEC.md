## 📌 一、 核心背景與需求痛點

在電腦型機台（及各類 IoT 對接機台）的完整上線閉環中，業務角色與技術角色具有明確的權責劃分：

1. **小猴（技術／機版工程師／裝機人員）**：
   - **關注點**：底層通訊與機電對接。
   - **具體任務**：SignalHub 設置、GPIO 脈衝映射（UI1~UI4 / 開分洗分反饋）、Callback URL、Webhook、Session End、HMAC 簽名等。
   - **業務痛點**：這類參數具專業門檻，老李（機台主／營運商）完全不懂也不需要懂。

2. **老李（機台主／營運商老闆）**：
   - **關注點**：商業營運與帳目結算。
   - **具體任務**：點數計價（一分多少元 `point_to_twd`）、開分面額級距、單次上限、設備歸屬場地（`venue_id` 在誰家）、分潤比例等。
   - **業務目標**：商業參數設妥後，機台即開始採集脈衝、計算營收並進行月結帳目。

3. **老李與小猴的協同關係（臨時委任）**：
   - 老李通常委託小猴到現場裝機或遠端配置。
   - 老李需要能快速幫小猴開一個**技術專用帳號**。
   - 小猴完成配對上線後，老李可能需要**隨手刪除該帳號**，或由系統設定效期自動過期回收。
   - 若老李懂技術或無外包人員，亦可自己操作該流程。

## 🔍 二、 現況技術盤點與系統斷點

目前 Owner 後台（`https://iot.tg25.win`）已有 `/users`（用戶管理）頁面，但尚未能滿足上述流暢閉環：

| 檢查項目 | 當前狀態 | 系統斷點與問題 |
| :--- | :--- | :--- |
| **帳號建立能力** | ✅ 已具備功能 | 老李可建立子帳號，`root_id` 自動歸屬於老李。 |
| **角色規範** | ❌ 角色寫死 | 後端建立邏輯寫死為 `sub_agent` 或 `staff`，資料庫尚未定義 `technician`（小猴）角色。 |
| **跨系統授權** | ❌ 技術設定隔離 | 小猴核心操作主要在 **SignalHub**（`signal.tg25.win`），老李在 Owner 開的帳號無法連動 SignalHub 技術參數授權。 |
| **帳號生命週期** | ⚠️ 缺少刪除機制 | 目前 `/users` 僅有「啟用／停用（toggleStatus）」，無「刪除帳號（destroy）」功能，不符老李「配對完即刪」之安全預期。 |
| **介面資訊分離** | ⚠️ 部分重疊 | 目前設備設置彈窗尚未將「工程師技術介面」與「老闆營運介面」進行權限隔離視圖展示。 |

## 💡 三、 具體改善建議規格（供 HQ 評估派工）

### 1. 資料庫與角色模型擴充（Ina 評估）
- `users.role` 新增 `technician`（技術工程師／小猴）。
- 或在 `users` 表中支援效期欄位（如 `expires_at`），提供臨時帳號自動失效。

### 2. 老李端用戶管理優化（Sophie 負責）
- **老李建立角色選擇**：
  - 老闆可在 `/users` 選擇新增「技術工程師（小猴）」角色。
- **帳號刪除機制**：
  - 新增 `DELETE /users/{id}` API，老李可刪除所屬的臨時技術帳號（嚴禁刪除有財務關聯帳號，但純技術帳號允許物理/邏輯刪除）。
- **可視範圍限制**：
  - 小猴帳號登入後，**不顯示**任何財務報表、營收、分潤協議等商業機密，僅顯示指派設備的技術調試介面。

### 3. 與 SignalHub 的協同（Sidney 協同）
- 小猴獲取臨時授權後，可透過統一認證（SSO 或專屬 Token）跳轉至 SignalHub 對應設備的配對頁面設定 Callback / Webhook / GPIO。
- 技術配置完成後自動回報同步至設備狀態。
