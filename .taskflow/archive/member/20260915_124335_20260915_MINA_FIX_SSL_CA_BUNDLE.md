## 📋 任務內容

## 優先級：最高（使用者的機台通訊可能已中斷）

## 問題描述
P0-5 把 DeviceController + KioskController 的 verify 從 false 改成 true，這是正確的安全修復。
但 VPS (129.146.103.177) 缺少 CA bundle，導致所有對 Infra API (api.tg25.win) 的 HTTPS 請求失敗：
  cURL error 60: SSL certificate problem: unable to get local issuer certificate

影響範圍：
- DeviceController::fetchDeviceActiveStatus() — 機台活躍狀態查詢失敗
- CheckOfflineSessions — 可能誤踢正在遊戲中的玩家
- 任何其他 Member→Infra 的 HTTP 呼叫

## 兩個修復方案（擇一）

### 方案 A（推薦）：在 VPS 安裝/更新 CA bundle
需要 ssh 到 VPS 執行：
  sudo apt-get update && sudo apt-get install -y ca-certificates
  sudo update-ca-certificates
然後確認 PHP 的 openssl.cafile 或 curl.cainfo 指向正確路徑。
（此步驟可能需要 HQ 或 Ina 協助，因為 Mina 可能無 sudo 權限）

### 方案 B（臨時但安全）：在 Guzzle 請求中指定 CA bundle 路徑
在 DeviceController 和 KioskController 的 HTTP 請求中：
  verify => /etc/ssl/certs/ca-certificates.crt（或 VPS 上實際的 CA bundle 路徑）
而非單純的 verify => true

## 修復後驗證（必做）
1. ssh 到 VPS，執行 php -r "echo file_get_contents(https://api.tg25.win/api/device/SR9ADYXPDYT1TUF7/active-status);" 不報 SSL 錯
2. curl -v https://api.tg25.win 確認 SSL handshake 正常
3. 在 Member 端 curl 測試 /api/kiosk/session-status 等依賴 Infra 的端點正常
4. 首頁、play 頁不受影響
