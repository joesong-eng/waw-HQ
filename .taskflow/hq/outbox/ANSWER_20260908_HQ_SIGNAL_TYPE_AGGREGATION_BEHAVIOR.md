## ✅ HQ 正式決策與技術標準澄清

### 一、WAW Signal Standard v1.0 官方定義澄清

經查閱當前標準文檔與 Coli 韌體實作 (v1.0.27)，**正式確認**：

#### UI2 的標準語義定義

**UI2 = 洗分/出金事件觸發（按鈕或觸發信號）**

- **硬體接線**：接「洗分按鈕」的光耦輸出
- **信號類型**：PCNT 硬體脈衝計數器（支援累計）
- **業務語義**：玩家請求洗分的**觸發次數**，而非實際退幣數量
- **韌體行為**：
  - 每次按下洗分按鈕 = `delta: 1`
  - `raw_value` 累計洗分請求總次數（里程表模式）
  - 發送 `credit_out` 事件，通知合作端「有洗分請求」
- **實際退分數量**：由**遊戲商伺服器**在 Webhook 回應中的 `actual_points` 返回

#### 當前韌體實作確認（Coli v1.0.27）

```c
// src/modules/signal_collector.c
// UI2 接 PIN_UI2 (IO14)，使用 PCNT 硬體計數器
pcnt_unit_create(PIN_UI2, polarity, &s_unit_ui2);

// 偵測到脈衝變化時
ESP_LOGI(TAG, "UI2 (出金) +%d，64-bit 累計 %llu", diff_ui2, s_count_ui[1]);
usb_cdc_send_pulse_event("credit_out", "UI2", s_count_ui[1], (uint32_t)diff_ui2);
```

✅ **結論**：韌體層面 UI2 = 洗分觸發事件，符合當前標準。

### 二、標準推薦接線配置

HQ 正式推薦配置：**方案 A + 可選擴展**

#### 🔧 標準配置（適用於大多數場景）

| 引腳 | 接線對象 | 信號類型 | 業務語義 |
|------|---------|---------|---------|
| **UI1** | 開分按鈕 / 投幣器脈衝 | PCNT 計數 | 玩家開分請求次數 |
| **UI2** | 洗分按鈕 / 洗分觸發 | PCNT 計數 | 玩家洗分請求次數 |
| UI3 | （預留） | GPIO 中斷 | 可選：狀態感測 / 警報 |
| UI4 | （預留） | GPIO 中斷 | 可選：輔助輸入 |

**核心原則**：
- ✅ UI1/UI2 監控「玩家意圖」（按鈕觸發）
- ✅ 實際開分/洗分數量由**遊戲商伺服器**計算並在 Webhook 回應中返回
- ✅ 採集卡**不參與金額換算**，僅忠實上報硬體觸發事件

#### 🔧 擴展配置（需要獨立監控實際退幣數量的場景）

如果現場有「退幣馬達計數脈衝」且需要獨立監控：

| 引腳 | 接線對象 | 信號類型 | 業務語義 |
|------|---------|---------|---------|
| **UI1** | 開分按鈕 | PCNT 計數 | 玩家開分請求次數 |
| **UI2** | 洗分按鈕 | PCNT 計數 | 玩家洗分請求次數 |
| **UI3** | 退幣馬達計數脈衝 | GPIO 中斷 / Counter | 實際退幣數量（審計用） |
| UI4 | （預留） | GPIO 中斷 | 其他輔助輸入 |

**應用場景**：
- 需要交叉驗證「洗分請求次數」與「實際退幣數量」
- 現場有退幣馬達且提供計數脈衝輸出
- 用於審計、對帳、防作弊檢測

⚠️ **注意**：UI3 使用 GPIO 中斷（非 PCNT），高頻脈衝可能影響性能，建議退幣馬達頻率 < 100Hz。

### 三、第三方對接文檔的描述方式

**決策**：✅ 明確說明 UI2 為「洗分請求通知」，實際退幣數由遊戲商決定

#### 需要在文檔中強調的重點

1. **信號語義明確化**：
   - UI1 = 開分按鈕觸發（非實際入金金額）
   - UI2 = 洗分按鈕觸發（非實際退幣數量）
   - `delta: 1` = 按鈕被按下一次（事件計數）

2. **責任邊界清晰化**：
   - 採集卡：忠實上報硬體觸發事件
   - 遊戲商：決定實際開分/洗分點數
   - SignalHub：轉發事件並記錄 `actual_points`

3. **Webhook 回應必填欄位**：
   ```json
   {
     "status": "success",
     "delivery_id": "del_10284",
     "actual_points": 3500,  // ← 必填：實際洗分點數
     "message": "洗分結算完成"
   }
   ```
