## 一、 測試背景與目標

Sidney 已完成 SignalHub 的功能收斂與線上部署（最新里程碑 Commit 4e6a5fc / Git Tag milestone-v1.2-signalhub-ui-audit-complete）。
為了確保生產環境對接的穩定性、排版大字清晰、帳務安全防呆，以及業務流程的無縫閉環，HQ 設計本測試規範。

### 核心目標：
1. **純淨零狀態 (Clean Slate)**：刪除所有舊測試採集卡與歷史設定檔，並徹底清空開洗分的歷史紀錄（信號事件、Webhook 派送記錄、模擬終端日誌歸零）。
2. **真實業務閉環**：模擬硬體盟友（硬體供應商）全新出貨 3 台 ESP32-S3 採集卡至老李名下，老李登入完成批量設置、腳位映射、Webhook 回調對接、硬體模擬觸發與日誌查核。
3. **100% 全功能覆蓋**：涵蓋認證隔離、待設置提示、批量設置精靈、設定檔 CRUD、8 路腳位與輸出繼電器、單一 Webhook 端點、HMAC 簽名、硬體模擬器雙排佈局與通道過濾、Mock 終端接收、非同步 ACK 回寫、派送記錄純文字指標與內部獨立滾動等。

## 三、 測試數據起點與環境重置規範

在測試啟動時，必須執行以下精確重置：

### 1. 舊採集卡與設定檔刪除
- **刪除範圍**：老李 (owner_id: 11) 名下的所有採集卡與相關資料。
  - devices：刪除舊測試設備（WAW-COLI-S3-001/002, C8F09E010001~05 等）。
  - signal_profiles：刪除關聯機台設定檔。
  - signal_pin_mappings：刪除關聯腳位映射規則。
  - signal_stat_rules：刪除關聯統計規則。
  - signal_webhooks：刪除舊 Webhook 配置。

### 2. 開洗分歷史紀錄徹底清零（零污染）
- **signal_events**：清空 (TRUNCATE)，歷史硬體脈衝與開洗分事件計數重置為 0。
- **signal_webhook_deliveries**：清空 (TRUNCATE)，Webhook 派送流水與審計日誌重置為 0。
- **Cache / Redis 快取清理**：
  - 清空 mock_callback_logs（模擬接收終端日誌歸零）。
  - 清空 mock_callback_seq（序號計數器歸零）。
  - 清空 test_webhook_logs_*。
- **交付記錄指標零狀態驗證**：進入 /signal-hub/deliveries，4 大指標必須呈現：
  - 今日派送: 0
  - 派送成功率: 0.0%
  - 平均延遲: 0ms
  - 失敗總數: 0

### 3. 硬體供應商全新出貨規格
硬體供應商正式建立出貨單，出貨 **3 台全新 ESP32-S3 採集卡** 給老李：
- **卡片 1**：Chip ID: C8F09E030001｜名稱：採集卡(模擬測試)#01｜狀態：pending_setup｜通電時間：now()
- **卡片 2**：Chip ID: C8F09E030002｜名稱：採集卡(模擬測試)#02｜狀態：pending_setup｜通電時間：now()
- **卡片 3**：Chip ID: C8F09E030003｜名稱：採集卡(模擬測試)#03｜狀態：pending_setup｜通電時間：now()
- 歸屬：owner_id = 11（老李）

## 四、 逐步測試執行案例矩陣 (10 大階段)

```
[階段 1: 數據徹底清零 & 出廠出貨] ──→ 驗證資料庫 0 歷史、3 台 pending 卡片入庫
       ↓
[階段 2: 老李登入 & 待設置區塊驗證] ──→ 驗證 profiles 頁面頂部橘色「⚠️ 待設置採集卡 (3)」
       ↓
[階段 3: 3-Step 批量設置精靈] ──→ 批量命名「老李戰神 #01~#03」、定義 UI1/UI2，綁定 Webhook
       ↓
[階段 4: 設定檔管理功能查驗] ──→ 驗證關鍵字搜尋、行業篩選、重命名「老李 VIP #03」、複製與刪除
       ↓
[階段 5: 8 路腳位與輸出繼電器] ──→ 驗證細項腳位設定、啟用 UO1 輸出繼電器、設定脈衝比例
       ↓
[階段 6: Webhook 單一端點與金鑰] ──→ 驗證 Callback URL、[↗ 開啟網址]、金鑰重生、原生中文測試發送
       ↓
[階段 7: 硬體信號模擬器 (開洗分)] ──→ 驗證動態過濾通道、點擊 U1(開分 10 脈衝)、U2(洗分 10 脈衝)
       ↓
[階段 8: 接收終端與雙向回調驗證] ──→ 驗證 /mock/callback 接收格式、驗簽、非同步 ACK 帶回 cleared_points
       ↓
[階段 9: 派送記錄與帳務防呆審計] ──→ 驗證 4 大指標從 0 開始累計、發送值整數 1、無重試按鈕、內部獨立滾動
       ↓
[階段 10: 異常容錯與故障測試] ──→ 模擬接收端 500 報錯，驗證失敗標記與指標安全累計
```

## 五、 驗收與交付標準

1. **零口頭回報**：每一階段必須具備真實資料庫 SQL 查詢快照、HTTP Status Code 或截圖/日誌證明。
2. **零殘留與零重複計費**：派送記錄不得提供手動重試以保障現場帳目純淨。
3. **文檔封存**：測試完成後，執行日誌將收錄至 .taskflow/ 與知識庫。
