# iHub UI 狀態機規格

> **最後更新**：2026-05-09 UTC+8  
> **目的**：定義每個用戶操作對應的視覺反饋，Hubie 實作時必須照此規格，不得自行決定。  
> **原則**：每個操作都有三個階段——**立即反饋 → 等待中 → 結果**，缺一不可。

---

## 畫面狀態總覽

```
idle
  │ 用戶點擊螢幕
  ▼
qr_ready（顯示 QR Code，等待掃碼）
  │ 收到 .MemberBoundToKiosk
  ▼
active（投幣中）
  │ 收到 .KioskSessionEnded
  ▼
completed（結算畫面）
  │ 8 秒後自動
  ▼
idle
```

---

## 各畫面狀態規格

### 1. idle（待機）

| 元素 | 顯示內容 |
|------|---------|
| 主畫面 | 「點擊螢幕開始兌幣」 |
| 副標 | 「掃碼後投入鈔票，即可自動完成兌換」 |

**用戶操作**：點擊螢幕任意位置  
**立即反饋**：畫面閃爍（紫色半透明 flash），**立刻**切換到 qr_ready，不等 API  
**等待中**：QR canvas 顯示 loading spinner  
**結果**：QR Code 渲染完成，spinner 消失  
**失敗**：顯示錯誤訊息，留在 qr_ready，不自動退回 idle

---

### 2. qr_ready（顯示 QR Code）

| 元素 | 顯示內容 |
|------|---------|
| QR Code | `KIOSK:{kiosk_id}:TOKEN:{token}` |
| 倒數計時 | 300 秒圓形進度條 |
| 說明 | 「請用手機掃描 QR Code」 |

**倒數到 0**：自動回到 idle，不請求新 token  
**收到 .MemberBoundToKiosk（status=bound）**：立刻切換到 active

---

### 3. active（投幣中）

#### 3a. 正常待機（等待投幣）

| 元素 | 顯示內容 |
|------|---------|
| 會員資訊 | 名稱、#ID、手機末 4 碼（無手機則不顯示）、代幣餘額 |
| 主提示 | 「請投入鈔票」+ AWAITING DEPOSIT 動畫 |
| 進度條 | 5 分鐘 idle timer（紫色，從右往左縮短） |
| 按鈕 | 「確認完成兌換」、「✕ 結束 {name}（#{id}）的兌換」 |

---

#### 3b. Escrow Modal（收到投幣，等待確認）

**觸發**：收到 `.KioskEscrowPending`  
**顯示**：覆蓋在 active 畫面上的 modal

| 元素 | 顯示內容 |
|------|---------|
| 會員資訊 | 名稱、手機（前 4 碼 + *** + 後 3 碼） |
| 金額 | 面額（100 / 500 / 1000 元） |
| 代幣 | 預計入帳代幣數 |
| 倒數 | 15 秒進度條（紅色，從右往左縮短） |
| 按鈕 | 「確認入帳」（綠色）、「取消退鈔」（紅色） |

**用戶操作：按「確認入帳」**

| 階段 | 畫面顯示 | 持續時間 |
|------|---------|---------|
| 立即反饋 | Modal 關閉，主畫面顯示「⏳ 處理中，請稍候...」（黃色） | 直到收到結果 |
| 等待中 | 持續顯示「⏳ 處理中...」，按鈕 disabled | 通常 1-3 秒 |
| 成功 | 切換成「✅ +{tokens} 代幣，餘額 {balance}」（綠色），代幣動畫 | 3 秒 |
| 3 秒後 | 隱藏提示，回到正常待機（3a） | — |
| 失敗（API 錯誤） | 顯示「❌ 確認失敗，請重試」（紅色） | 3 秒後隱藏 |

**用戶操作：按「取消退鈔」**

| 階段 | 畫面顯示 |
|------|---------|
| 立即反饋 | Modal 關閉，顯示「↩ 退鈔中...」（灰色） |
| 結果 | 1 秒後隱藏，回到正常待機（3a） |

**15 秒倒數到 0（未操作）**

| 階段 | 畫面顯示 |
|------|---------|
| 立即 | Modal 關閉，顯示「⏱ 確認超時，鈔票將自動退回」（橘色） |
| 結果 | 3 秒後隱藏，回到正常待機（3a） |
| 說明 | 韌體 Fail-Safe 會自動退鈔，iHub 不需要呼叫任何 API |

---

#### 3c. 入帳成功後（收到 .KioskSessionUpdated）

> 這個事件是在「確認入帳」→ MQTT stack → 韌體吞鈔 → stacked 事件 → Member 入帳後才廣播，通常在按確認後 1-3 秒到達。

| 元素 | 顯示內容 |
|------|---------|
| 提示 | 「✅ +{tokens_credited} 代幣，餘額 {member_balance}」（綠色） |
| 動畫 | 代幣爆炸動畫（triggerBurst） |
| 持續 | 3 秒後隱藏 |
| 同時 | 更新左側會員餘額顯示，重置 5 分鐘 idle timer |

---

#### 3d. 強制結束 / 確認完成兌換

**用戶操作：按「確認完成兌換」或「✕ 結束」**

| 階段 | 畫面顯示 |
|------|---------|
| 立即反饋 | 按鈕 disabled，顯示「⏳ 結束中...」 |
| 等待中 | 等待 .KioskSessionEnded 事件 |
| 收到事件 | 切換到 completed 畫面 |
| API 失敗 | 顯示「❌ 結束失敗」，3 秒後回到 active，按鈕恢復 |

---

### 4. completed（結算）

| 元素 | 顯示內容 |
|------|---------|
| 圖示 | ✓（有入帳）或 ✕（無入帳） |
| 標題 | 「兌換完成」（有入帳）或「已結束兌換」（無入帳） |
| 金額 | 本次累計投幣金額 |
| 倒數 | 8 秒後自動回到 idle |

---

## 通用規則

1. **任何 API 呼叫都必須有 loading 狀態**，不能按下去沒反應
2. **loading 狀態持續到收到結果**，不能有固定時間的假 loading
3. **成功提示顯示 3 秒**，失敗提示顯示 3 秒，然後回到合理的下一個狀態
4. **按鈕在 loading 期間必須 disabled**，防止重複點擊
5. **網路錯誤要顯示**，不能靜默失敗
6. **超時（escrow 15 秒）要有明確提示**，告訴用戶發生了什麼
